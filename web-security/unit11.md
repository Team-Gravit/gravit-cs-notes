## 파일 업로드 취약점

**파일 업로드 기능**은 프로필 사진, 첨부 문서 등 현대 웹 서비스에 필수적이지만, 검증이 부실하면 **공격자가 서버에서 실행되는 악성 스크립트를 심는 통로**가 된다. 국내 침해사고에서 가장 빈번한 초기 침투 경로 중 하나이므로, 원리와 방어 체계를 정확히 이해해야 한다.

<br>

### 1. 파일 업로드 기능의 위험성

업로드 기능 자체는 정상 기능이지만, 서버가 **업로드된 파일의 종류와 내용을 제대로 검사하지 않으면** 실행 가능한 스크립트 파일이 서버에 저장될 수 있다. 이 파일이 웹을 통해 접근·실행되는 순간, 공격자는 서버의 권한으로 임의 명령을 수행할 수 있게 된다.

> ⚠️ 국내 웹 침해사고 분석에서 파일 업로드를 통한 웹쉘 설치는 **최다 초기 침투 경로** 중 하나로 반복해서 지목된다. 게시판, 문의하기, 이미지 업로드 등 사용자가 파일을 올릴 수 있는 모든 지점이 잠재적 공격 대상이다.

<br>

### 2. 웹쉘(Web Shell) 개념

**웹쉘**은 공격자가 업로드한 뒤 웹 요청으로 원격 조작하는 **서버 측 스크립트**다. 서버가 이 스크립트를 일반 프로그램처럼 실행하기 때문에, 공격자는 브라우저나 요청 도구만으로 서버 내부 명령 실행, 파일 열람, 데이터베이스 접근 등을 수행할 수 있다.

본 유닛에서는 방어 관점의 이해가 목적이므로 실제 웹쉘 코드는 다루지 않는다. 핵심은 **"실행 가능한 파일이 실행 가능한 위치에 저장되면 서버가 장악된다"** 는 개념이다.

<br>

### 3. 공격 흐름

전형적인 파일 업로드 공격은 다음과 같은 단계로 진행된다.

```
[1] 악성 스크립트 파일 업로드
        │  (확장자·타입 검증 우회)
        ▼
[2] 서버의 웹 접근 가능 경로에 저장됨
        │  예: /uploads/evil.jsp
        ▼
[3] 공격자가 해당 파일 URL로 직접 요청
        │  서버가 스크립트로 인식·실행
        ▼
[4] 서버 명령 실행 → 서버 장악(내부 정보 탈취·추가 침투)
```

핵심은 2단계와 3단계다. **웹 루트 안에 저장**되고 **실행 권한이 있으면** 공격이 성립한다.

<br>

### 4. 우회 기법 개요

공격자는 단순한 확장자 검사를 다양한 방법으로 우회하려 한다. 아래는 **방어 로직을 설계하기 위해** 알아야 할 우회 유형이다.

- **확장자 대소문자 조작**: `.PHP`, `.jSp`처럼 대소문자를 섞어 소문자만 비교하는 필터를 회피한다
- **이중 확장자**: `image.jpg.php`처럼 허용 확장자를 앞에 붙여 뒤쪽 실행 확장자를 숨긴다
- **Content-Type 조작**: 요청의 `Content-Type` 헤더를 `image/jpeg`로 위조해 타입 검사만 하는 서버를 속인다

> 💡 우회 기법이 다양하다는 사실은 **단일 검증만으로는 안전하지 않다**는 것을 의미한다. 그래서 방어는 하나의 검사가 아니라 여러 축을 겹쳐 쌓는 **다층 방어**(Defense in Depth)로 설계해야 한다.

<br>

### 5. 방어 1축 — 확장자 화이트리스트

**허용할 확장자 목록(화이트리스트)** 만 통과시키는 방식이다. 금지 목록(블랙리스트)은 새로운 실행 확장자나 대소문자·이중 확장자 변형을 모두 막을 수 없어 근본적으로 불완전하다.

| **방식**             | **원리**                         | **한계**                             |
| -------------------- | -------------------------------- | ------------------------------------ |
| **블랙리스트**       | 금지할 확장자를 나열해 차단      | 누락된 확장자·변형에 **우회 가능**   |
| **화이트리스트**     | 허용할 확장자만 통과             | 목록 관리 필요하나 **원칙적으로 안전** |

```java
// 확장자 화이트리스트 검증 (대소문자 무시, 이중 확장자 방지)
private static final Set<String> ALLOWED =
        Set.of("jpg", "jpeg", "png", "gif");

public boolean isAllowed(String filename) {
    // 마지막 '.' 뒤만 실제 확장자로 인정
    int dot = filename.lastIndexOf('.');
    if (dot < 0) return false;
    String ext = filename.substring(dot + 1).toLowerCase();
    return ALLOWED.contains(ext);
}
```

### 6. 방어 2축 — 파일 시그니처(매직 넘버) 검증

파일 확장자는 이름에 불과하므로, **파일의 실제 첫 바이트(매직 넘버)** 를 읽어 내용이 선언한 형식과 일치하는지 확인한다. 확장자를 `.jpg`로 위조해도 내부 바이트가 이미지가 아니면 걸러진다.

| **형식**  | **매직 넘버(첫 바이트)**   |
| --------- | -------------------------- |
| **JPG**   | `FF D8 FF`                 |
| **PNG**   | `89 50 4E 47`              |
| **GIF**   | `47 49 46 38`              |
| **PDF**   | `25 50 44 46`              |

```python
# 파일 시그니처(매직 넘버) 검증
SIGNATURES = {
    "jpg": b"\xFF\xD8\xFF",
    "png": b"\x89\x50\x4E\x47",
    "pdf": b"\x25\x50\x44\x46",
}

def verify_signature(file_bytes: bytes, ext: str) -> bool:
    magic = SIGNATURES.get(ext)
    if magic is None:
        return False
    return file_bytes.startswith(magic)
```

### 7. 방어 3축 — 저장 파일명 무작위화

업로드된 원본 파일명을 그대로 쓰면 공격자가 저장 경로와 파일명을 예측해 직접 접근할 수 있다. 저장 시 **무작위 값(UUID 등)으로 파일명을 교체**하면 접근 URL을 추측하기 어려워지고, 이중 확장자 같은 이름 기반 공격도 무력화된다.

```java
// 저장 파일명을 무작위 UUID로 교체
String ext = "jpg"; // 검증을 통과한 확장자만 사용
String storedName = UUID.randomUUID().toString() + "." + ext;
// 원본 파일명은 별도 컬럼에 표시용으로만 저장
```

<br>

### 8. 방어 4축 — 업로드 디렉토리 분리

가장 강력한 방어는 **애초에 실행되지 못하게 하는 것**이다. 업로드 파일을 **웹 루트 바깥에 저장**하고, 저장 위치에서 **스크립트 실행 권한을 제거**하면 웹쉘이 올라와도 실행되지 않는다.

```
[웹 루트 /var/www/html]  ← 스크립트 실행 O
        │  여기에 업로드 파일을 두지 않는다
        │
[별도 저장소 /data/uploads]  ← 웹 루트 밖, 실행 권한 제거
        │  다운로드는 서버 로직을 거쳐 스트리밍으로만 제공
        ▼
   설령 evil.jsp가 올라와도 웹으로 실행 불가
```

> 💡 실무에서는 업로드 파일을 아예 별도 스토리지(오브젝트 스토리지 등)에 두고 애플리케이션 서버와 분리하는 방식을 널리 사용한다. 실행 환경과 저장 공간을 분리한다는 원칙은 동일하다.

<br>

### 9. 방어 4축 요약

네 가지 방어를 겹쳐 적용해야 우회를 실질적으로 차단할 수 있다.

| **방어 축**             | **원리**                              | **막는 우회**                  |
| ----------------------- | ------------------------------------- | ------------------------------ |
| **확장자 화이트리스트** | 허용 확장자만 통과                    | 실행 확장자·대소문자 변형      |
| **파일 시그니처 검증**  | 실제 내용의 매직 넘버 확인            | Content-Type·확장자 위조       |
| **파일명 무작위화**     | 저장명을 UUID로 교체                  | 경로 예측·이중 확장자          |
| **디렉토리 분리**       | 웹 루트 밖 저장·실행 권한 제거        | 저장돼도 **실행 자체를 차단**  |
