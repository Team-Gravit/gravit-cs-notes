전체 또는 특정 과목의 unit 파일을 스캔해 품질 리포트와 개선 우선순위를 생성한다.

## 사용법
`/review-units [subject]`

예시:
- `/review-units` — 전체 5개 과목 스캔
- `/review-units algorithm` — algorithm/ 만 스캔
- `/review-units web-security` — web-security/ 만 스캔

## Arguments
$ARGUMENTS: 비어있으면 전체, 과목 디렉토리명이면 해당 과목만.

---

## 실행 지침

### Step 1 — 스캔 범위 결정

`$ARGUMENTS`가 비어있으면 다음 5개 과목을 모두 스캔한다:
`algorithm`, `data-structure`, `database`, `network`, `web-security`

과목명이 주어지면 해당 과목만 스캔한다.

각 과목 디렉토리에서 `unit*.md` 파일 목록을 수집한다.
`web-security`의 경우 `unit01/unit01.md` 중첩 구조도 포함하고 경로 이슈로 별도 표기한다.

### Step 2 — 파일별 메트릭 수집 (병렬)

독립적인 파일들은 병렬로 읽어 시간을 절약한다.

각 파일에서 다음 메트릭을 수집한다:

| 메트릭               | 측정 방법                                              |
| -------------------- | ------------------------------------------------------ |
| `lines`              | 전체 줄 수                                             |
| `sections`           | `### ` 으로 시작하는 줄 수                             |
| `callouts`           | `> 💡` 또는 `> ⚠️` 로 시작하는 줄 수                  |
| `inline_warnings`    | `❗️**` 를 포함하는 줄 수                              |
| `code_blocks`        | ` ``` ` 여는 펜스(언어 명시) 개수                      |
| `tables`             | `| --- ` 구분선 패턴을 포함하는 줄 수                  |
| `images`             | `<img` 태그 개수                                       |
| `br_tags`            | `<br>` 태그 개수                                       |
| `forbidden_headings` | `#### ` 으로 시작하는 줄 수                            |
| `starts_with_h2`     | 첫 번째 heading 줄이 `## ` 로 시작하는가 (yes/no)      |

### Step 3 — 점수 산정

각 파일에 대해 100점 기준으로 점수를 계산한다:

| 기준              | 배점 | 조건                                     |
| ----------------- | ---- | ---------------------------------------- |
| 최소 줄 수        | 20점 | ≥ 80줄 = 20점 / 50–79줄 = 10점 / < 50 = 0점 |
| 섹션 수           | 20점 | ≥ 6개 = 20점 / 4–5개 = 10점 / < 4개 = 0점  |
| callout 존재      | 15점 | ≥ 2개 = 15점 / 1개 = 8점 / 0개 = 0점    |
| 코드블록 존재     | 15점 | ≥ 1개 = 15점 / 0개 = 0점                |
| 표 존재           | 15점 | ≥ 1개 = 15점 / 0개 = 0점                |
| 금지 heading 없음 | 10점 | 0개 = 10점 / 1개 이상 = 0점             |
| 올바른 H2 시작    | 5점  | yes = 5점 / no = 0점                    |

등급: **A** (90–100) / **B** (75–89) / **C** (60–74) / **D** (40–59) / **F** (0–39)

### Step 4 — 리포트 출력

아래 형식으로 전체 리포트를 출력한다:

---

```
# 품질 리포트
생성일: (오늘 날짜)
검사 범위: (과목명 또는 "전체")

## 요약 테이블

| 파일 | 줄 | 섹션 | callout | 코드 | 표 | 점수 | 등급 |
| ---- | -- | ---- | ------- | ---- | -- | ---- | ---- |
| algorithm/unit01.md | 43 | 3 | 1 | 0 | 2 | 30 | F |
| ...  |    |      |         |      |    |      |      |

## 즉시 개선 필요 (D등급 / F등급)

점수 오름차순으로 정렬. 각 파일에 대해:
- 현재 점수 및 등급
- 주요 결함 상위 3가지
- 추천 명령어: `/improve-unit <file-path>`

## 개선 권장 (C등급, 60–74점)

각 파일에 대해 부족한 점 1–2가지 간략히 기술.

## 양호 (B등급 이상, ≥75점)

파일별 한 줄 상태 메모.

## 구조 이슈

다음 경우에 해당하는 파일을 별도 목록으로 표시:
- 잘못된 경로 구조 (예: web-security/unit01/unit01.md → web-security/unit01.md 이어야 함)
- `####` 금지 heading 발견
- `##` 최상단 제목 없음
- 빈 파일 (0줄 또는 공백만)

## 다음 단계 추천

1. 가장 먼저 개선할 파일 (최하위 점수, 최고 임팩트)
2. 신규 작성이 필요한 unit 여부 (`/write-unit` 제안)
3. 수동으로 처리해야 할 구조 이슈
```
