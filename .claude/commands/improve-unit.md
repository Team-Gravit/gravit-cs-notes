기존 CS 개념노트 unit 파일을 품질 기준에 맞게 검토하고 개선한다.

## 사용법
`/improve-unit <file-path>`

예시:
- `/improve-unit algorithm/unit01.md`
- `/improve-unit web-security/unit01.md`
- `/improve-unit data-structure/unit03.md`

## Arguments
$ARGUMENTS: 저장소 루트 기준 상대 경로.

---

## 실행 지침

### Step 1 — 파일 읽기

`$ARGUMENTS` 경로의 파일을 Read로 읽는다. `CLAUDE.md`와 `requirement.md`도 함께 읽어
전체 품질 기준을 컨텍스트로 확보한다.

### Step 2 — 구조 감사

다음 항목을 수동으로 확인하고 결과를 기록한다:

| 항목                   | 현재 값 | 최소 기준 (실패 임계값) | 개선 목표 | 통과 여부 |
| ---------------------- | ------- | ----------------------- | --------- | --------- |
| 줄 수                  |         | ≥ 80                    | ≥ 120     |           |
| `###` 섹션 수          |         | ≥ 4       |           |
| callout 블록 수        |         | ≥ 2       |           |
| fenced code block 수   |         | ≥ 1       |           |
| `<br>` 태그 존재       |         | 모든 섹션 |           |
| 최상단 `##` H2 제목    |         | 필수      |           |
| `####` 금지 heading    |         | 0개       |           |
| 한국어 작성            |         | 100%      |           |

### Step 3 — 콘텐츠 감사

다음 항목도 확인한다:

- [ ] 개요 문단이 명확한가 (첫 1–2문장에서 개념과 중요성 설명)
- [ ] 비교 표가 있는가
- [ ] 복잡도 분석이 있는가 (복잡도가 있는 주제일 경우)
- [ ] 실제 코드 예시가 있는가 (의사코드가 아닌 실행 가능한 코드)
- [ ] 다이어그램(이미지 또는 ASCII art)이 있는가
- [ ] 사용 사례 또는 다른 개념과의 비교가 있는가

감사 결과를 출력한 뒤 Step 4로 진행한다.

### Step 4 — 보완 자료 수집 (필요 시)

콘텐츠가 부족한 경우(예: 설명이 단순 목록만 있고 이유/맥락 없음, 코드 예시 없음),
WebSearch로 부족한 부분의 정보를 수집한다. 기존의 정확한 내용을 재검색할 필요는 없다.

### Step 5 — 개선 적용

감사에서 실패한 항목을 모두 수정한다. 구체적인 개선 방법:

**설명/섹션이 빈약한 경우:**
- 불릿 목록을 구체적인 이유와 맥락이 있는 완전한 문장으로 확장
- "왜 이 개념이 중요한가" 설명 추가

**코드 예시가 없는 경우:**
- Python 또는 Java로 개념을 보여주는 fenced code block 추가
- 인라인 주석은 한국어로 작성

**callout이 부족한 경우:**
- 언어별 특이사항, 흥미로운 인사이트 → `> 💡` 추가
- 자주 하는 실수, 성능 주의사항 → `> ⚠️` 추가
- 동작 설명 중 엣지 케이스 → `❗️**...**` 추가

**비교 표가 없는 경우:**
- 관련 개념과의 비교 표 추가 (예: 시간복잡도별 비교, 자료구조 비교)

**`<br>` 누락된 경우:**
- 모든 `###` 섹션 사이에 `<br>` 태그 삽입

**`####` 금지 heading이 있는 경우:**
- `#### 소제목` → 해당 내용 앞에 `<br>` 추가 후 `**소제목**` 볼드 텍스트로 변환

**절대 하지 말아야 할 것:**
- 기존에 정확한 내용 삭제 또는 의미 변경
- 주제 범위를 벗어난 내용 추가
- 실제 존재 여부가 확인되지 않은 이미지 태그 추가 (ASCII 다이어그램으로 대체)

### Step 6 — 변경 요약 출력

파일 편집 완료 후 아래 형식으로 요약을 출력한다:

```
✅ 개선 완료: <file-path>

변경 전 → 변경 후
  줄 수: N줄 → N줄
  섹션: N개 → N개
  callout: N개 → N개
  코드블록: N개 → N개

주요 변경 사항:
  - [추가] 코드 예시 (Python): ### N섹션
  - [추가] callout N개 (💡 N개, ⚠️ N개)
  - [추가] 복잡도 비교 표
  - [수정] <br> 누락 N곳 추가
  - [수정] #### 금지 heading N개 볼드 텍스트로 변환
```
