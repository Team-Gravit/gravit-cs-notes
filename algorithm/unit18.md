## 재귀와 분할 정복(Recursion & Divide and Conquer)

**재귀(Recursion)** 는 함수가 자기 자신을 호출하여 문제를 해결하는 기법이고, **분할 정복(Divide and Conquer)** 은 재귀를 기반으로 큰 문제를 작은 부분 문제로 나누어 해결한 뒤 결과를 결합하는 알고리즘 설계 패러다임이다. 합병 정렬(unit08), 퀵 정렬(unit09), 이진 탐색 등 핵심 알고리즘의 공통 기반이 된다.

<br>

### 1. 재귀의 정의

재귀 함수는 반드시 다음 두 가지 요소로 구성된다.

- **기저 조건(Base Case)**: 더 이상 재귀 호출을 하지 않고 값을 반환하는 종료 조건
- **재귀 호출(Recursive Call)**: 문제의 크기를 **줄여서** 자기 자신을 다시 호출하는 부분

```python
def factorial(n):
    if n <= 1:          # 기저 조건
        return 1
    return n * factorial(n - 1)  # 크기를 줄인 재귀 호출
```

❗️**기저 조건 누락**: 기저 조건이 없거나 호출마다 문제의 크기가 줄어들지 않으면 무한 재귀에 빠져 프로그램이 비정상 종료된다.

<br>

### 2. 호출 스택의 동작

재귀 호출이 일어날 때마다 **스택 프레임**(매개변수, 지역 변수, 복귀 주소)이 호출 스택에 쌓이고, 함수가 반환되면 역순으로 해제된다.

```
factorial(3) 호출 시 스택 변화

[쌓임]                          [해제]
| factorial(1) | ← 기저 조건    | return 1      |
| factorial(2) |                | return 2*1=2  |
| factorial(3) |                | return 3*2=6  |
+--------------+                +---------------+
  깊이 3까지 쌓인 뒤, 위에서부터 차례로 반환
```

즉 재귀는 **가장 나중에 호출된 함수가 가장 먼저 반환**되는 스택(LIFO) 구조 위에서 동작한다.

<br>

### 3. 스택 오버플로 위험

호출 스택의 크기는 유한하므로, 재귀 깊이가 지나치게 깊어지면 **스택 오버플로(Stack Overflow)** 가 발생한다.

> ⚠️ Python은 기본 재귀 깊이 제한이 약 1,000이며 초과 시 `RecursionError`가 발생한다. `sys.setrecursionlimit()`으로 한도를 늘릴 수 있지만, 근본적으로는 반복문 변환이나 명시적 스택 사용을 고려해야 한다.

<br>

### 4. 꼬리 재귀와 최적화

**꼬리 재귀(Tail Recursion)** 는 재귀 호출이 함수의 **마지막 연산**인 형태다. 반환 후 추가 계산이 없으므로, 이를 지원하는 컴파일러는 새 스택 프레임을 쌓지 않고 반복문처럼 최적화(꼬리 호출 최적화)할 수 있다.

```python
def factorial_tail(n, acc=1):
    if n <= 1:
        return acc
    return factorial_tail(n - 1, acc * n)  # 마지막 연산이 재귀 호출
```

> 💡 Python과 Java는 꼬리 호출 최적화를 **지원하지 않는다**. 따라서 두 언어에서는 꼬리 재귀 형태라도 스택이 계속 쌓이며, 깊은 재귀는 아래처럼 **반복문으로 직접 변환**하는 것이 안전하다.

```python
def factorial_iter(n):
    acc = 1
    for i in range(2, n + 1):
        acc *= i
    return acc
```

### 5. 재귀 vs 반복 비교

| **항목**        | **재귀**                          | **반복**                     |
| --------------- | --------------------------------- | ---------------------------- |
| **가독성**      | 문제 구조를 그대로 표현, 간결함   | 코드가 길어질 수 있음        |
| **메모리**      | 스택 프레임 누적 **O(깊이)**      | 추가 스택 없음 **O(1)**      |
| **속도**        | 함수 호출 오버헤드 존재           | 상대적으로 빠름              |
| **위험 요소**   | **스택 오버플로** 가능            | 무한 루프 가능               |
| **적합한 문제** | 트리 순회, 백트래킹, 분할 정복    | 단순 누적 계산, 선형 순회    |

<br>

### 6. 분할 정복의 3단계

분할 정복은 재귀 구조를 이용해 다음 3단계로 문제를 해결한다.

1. **분할(Divide)**: 문제를 같은 형태의 더 작은 부분 문제로 나눈다.
2. **정복(Conquer)**: 부분 문제가 충분히 작으면 직접 해결하고, 아니면 재귀적으로 해결한다.
3. **결합(Combine)**: 부분 문제의 해를 합쳐 원래 문제의 해를 만든다.

```
        [8개 문제]
        /        \
   [4개]          [4개]      ← 분할
   /   \          /   \
 [2개] [2개]   [2개] [2개]   ← 크기 1까지 분할 후 정복
   \   /          \   /
   [4개 해]      [4개 해]    ← 결합
        \        /
        [전체 해]
```

<br>

### 7. 분할 정복 대표 사례

| **알고리즘**              | **분할 방식**                | **시간 복잡도**   | **관련 유닛** |
| ------------------------- | ---------------------------- | ----------------- | ------------- |
| **합병 정렬**             | 절반씩 균등 분할 후 합병     | **O(n log n)**    | unit08        |
| **퀵 정렬**               | 피벗 기준 비균등 분할        | 평균 **O(n log n)** | unit09      |
| **이진 탐색**             | 탐색 범위를 절반으로 축소    | **O(log n)**      | unit19        |
| **거듭제곱(분할 거듭제곱)** | 지수를 절반으로 축소       | **O(log n)**      | -             |

합병 정렬은 **결합(합병) 과정**이 핵심이고, 퀵 정렬은 **분할(파티션) 과정**이 핵심이라는 점에서 대비된다. 이진 탐색은 분할 후 **한쪽 부분 문제만** 남기는 특수한 형태다.

<br>

### 8. 피보나치 재귀의 중복 호출 문제

단순 재귀가 항상 효율적인 것은 아니다. 피보나치 수를 단순 재귀로 구하면 **동일한 부분 문제가 반복 계산**된다.

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)  # O(2^n) — 지수적 폭발
```

```
              fib(5)
            /        \
       fib(4)        fib(3)
      /      \      /      \
  fib(3)  fib(2)  fib(2)  fib(1)
   ...      ...    ...
  → fib(3)이 2번, fib(2)가 3번 중복 계산됨
```

> 💡 이러한 중복 호출은 계산 결과를 저장해 재사용하는 **동적 프로그래밍(unit15)** 의 메모이제이션으로 해결할 수 있다. 분할 정복은 부분 문제가 **겹치지 않을 때**, DP는 부분 문제가 **겹칠 때** 적합하다.
