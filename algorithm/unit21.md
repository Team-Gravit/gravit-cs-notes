## 투 포인터와 슬라이딩 윈도우

**투 포인터**는 배열에서 두 개의 포인터를 이동시키며 원하는 조건을 만족하는 구간이나 쌍을 찾는 기법이고, **슬라이딩 윈도우**는 일정 범위(윈도우)를 한 칸씩 밀며 구간 정보를 갱신하는 기법이다. 두 기법 모두 이중 반복문 **O(n²)** 풀이를 **O(n)** 으로 개선하는 대표적인 최적화 도구다.

<br>

### 1. 투 포인터의 핵심 개념

- 배열을 순회할 때 **인덱스 변수 2개**(포인터)를 함께 사용함
- 각 포인터는 조건에 따라 **한 방향으로만 이동**하므로, 두 포인터가 이동하는 총 횟수는 최대 `2n`번임 → 전체 **O(n)**
- 포인터 배치 방식에 따라 두 가지 유형으로 나뉨

<br>

### 1-1. 양끝에서 시작하는 방식

- 포인터를 배열의 **양 끝**(`left = 0`, `right = n-1`)에 두고 서로 마주 보며 좁혀감
- **정렬된 배열**에서 두 수의 합, 팰린드롬 판별 등에 사용됨

<br>

### 1-2. 같은 방향으로 이동하는 방식

- 두 포인터(`start`, `end`)가 모두 **왼쪽 끝에서 출발**해 같은 방향으로 전진함
- 조건을 만족하면 `start`를 당겨 구간을 줄이고, 부족하면 `end`를 밀어 구간을 늘림
- **부분 배열(연속 구간)의 합**, 조건을 만족하는 최소/최대 구간 찾기에 사용됨

<br>

### 2. 대표 문제: 정렬된 배열에서 두 수의 합

정렬된 배열에서 합이 `target = 10`이 되는 두 수를 찾는 과정이다. 합이 크면 `right`를 왼쪽으로, 작으면 `left`를 오른쪽으로 이동한다.

```
target = 10

[1, 3, 5, 7, 9]
 L           R    1 + 9 = 10  →  정답 발견? (예시 계속)

[1, 3, 5, 7, 9]
 L        R       합이 크면 R을 왼쪽으로 이동 (7 + 9 = 16 > 10 인 경우)

[1, 3, 5, 7, 9]
    L     R       합이 작으면 L을 오른쪽으로 이동 (1 + 7 = 8 < 10 인 경우)

[1, 3, 5, 7, 9]
       L  R       3 + 7 = 10  →  정답
```

❗️**전제 조건**: 양끝 투 포인터로 두 수의 합을 찾으려면 배열이 반드시 **정렬**되어 있어야 한다. 정렬되지 않은 배열이라면 먼저 O(n log n) 정렬을 수행하거나 해시 테이블을 사용한다.

<br>

### 3. 대표 문제: 부분 배열의 합

합이 `target = 5`인 **연속 부분 배열**의 개수를 세는 문제다. `start`와 `end`가 같은 방향으로 이동한다.

```
target = 5

[1, 2, 3, 2, 1]
 S  E             구간합 1+2 = 3  < 5  →  E 전진

[1, 2, 3, 2, 1]
 S     E          구간합 1+2+3 = 6  > 5  →  S 전진

[1, 2, 3, 2, 1]
    S  E          구간합 2+3 = 5  = 5  →  개수 +1, E 전진

[1, 2, 3, 2, 1]
       S  E       구간합 3+2 = 5  = 5  →  개수 +1
```

> 💡 이 방식이 성립하려면 원소가 모두 **양수**여야 한다. 음수가 섞여 있으면 구간을 늘려도 합이 줄어들 수 있어 포인터의 단방향 이동 논리가 깨지며, 이 경우 **누적 합 + 해시 테이블** 방식을 사용한다.

<br>

### 4. 슬라이딩 윈도우

**윈도우(구간)** 를 오른쪽으로 한 칸씩 밀면서, 새로 들어오는 원소를 더하고 빠져나가는 원소를 빼는 방식으로 구간 정보를 **재계산 없이 갱신**한다.

```
크기 3인 윈도우의 이동 (구간 합 갱신)

[2, 5, 1, 4, 3]
 ─────────
 (2+5+1=8)

[2, 5, 1, 4, 3]
    ─────────
 8 - 2 + 4 = 10   ← 앞 원소 제거, 새 원소 추가

[2, 5, 1, 4, 3]
       ─────────
 10 - 5 + 3 = 8
```

<br>

### 4-1. 고정 크기 윈도우와 가변 크기 윈도우

| **구분**      | **고정 크기 윈도우**             | **가변 크기 윈도우**                     |
| ------------- | -------------------------------- | ---------------------------------------- |
| **윈도우 폭** | 항상 **k로 일정**                | 조건에 따라 **늘었다 줄었다** 함         |
| **이동 방식** | 양쪽 끝이 **동시에 한 칸씩** 전진 | 두 포인터가 **독립적으로** 전진          |
| **대표 문제** | 크기 k인 구간의 최대 합          | 합이 target 이상인 **최소 길이** 부분 배열 |

> 💡 가변 크기 슬라이딩 윈도우는 같은 방향 투 포인터와 사실상 동일한 기법이며, "구간"의 관점을 강조할 때 슬라이딩 윈도우라고 부른다.

<br>

### 5. 누적 합(Prefix Sum)과의 연계

**누적 합**은 `prefix[i] = arr[0] + ... + arr[i-1]`을 미리 계산해 두는 기법으로, 임의 구간 `[l, r]`의 합을 **O(1)** 에 구할 수 있다.

```
구간합(l, r) = prefix[r+1] - prefix[l]
```

- 슬라이딩 윈도우는 구간이 **한 칸씩 연속적으로 이동**할 때 유리함
- 누적 합은 **임의의 구간**에 대한 질의가 여러 번 들어올 때 유리함
- 두 기법 모두 "구간 합을 매번 다시 더하는 낭비"를 제거한다는 점에서 목적이 같음

<br>

### 6. Python 구현 예시

```python
# 1) 양끝 투 포인터: 정렬된 배열에서 두 수의 합
def two_sum_sorted(arr, target):
    left, right = 0, len(arr) - 1
    while left < right:
        s = arr[left] + arr[right]
        if s == target:
            return (left, right)
        elif s < target:
            left += 1      # 합을 키워야 하므로 왼쪽 포인터 전진
        else:
            right -= 1     # 합을 줄여야 하므로 오른쪽 포인터 후퇴
    return None


# 2) 가변 크기 슬라이딩 윈도우: 합이 target 이상인 최소 길이 부분 배열
def min_subarray_len(arr, target):
    start, window_sum = 0, 0
    answer = float('inf')
    for end in range(len(arr)):
        window_sum += arr[end]            # 윈도우 확장
        while window_sum >= target:
            answer = min(answer, end - start + 1)
            window_sum -= arr[start]      # 윈도우 축소
            start += 1
    return answer if answer != float('inf') else 0
```

### 7. O(n²) → O(n) 개선 비교

| **문제**                     | **브루트 포스**                       | **투 포인터/슬라이딩 윈도우**       |
| ---------------------------- | ------------------------------------- | ----------------------------------- |
| **두 수의 합** (정렬 배열)   | 모든 쌍 검사 → **O(n²)**              | 양끝 포인터 → **O(n)**              |
| **부분 배열의 합**           | 모든 구간 합 계산 → **O(n²)**         | 같은 방향 포인터 → **O(n)**         |
| **크기 k 구간의 최대 합**    | 구간마다 k개 합산 → **O(nk)**         | 고정 윈도우 갱신 → **O(n)**         |

> ⚠️ 두 포인터가 각각 중첩 반복문 안에서 뒤로 되돌아가면 O(n)이 보장되지 않는다. 각 포인터가 **단조롭게 한 방향으로만 이동**하는지 반드시 확인해야 한다.

<br>

### 8. 복잡도 정리

| **기법**              | **시간 복잡도** | **공간 복잡도** | **비고**                       |
| --------------------- | --------------- | --------------- | ------------------------------ |
| **양끝 투 포인터**    | O(n)            | O(1)            | 정렬 필요 시 O(n log n) 추가   |
| **같은 방향 투 포인터** | O(n)          | O(1)            | 원소가 양수일 때 성립          |
| **슬라이딩 윈도우**   | O(n)            | O(1)            | 구간 정보 O(1) 갱신            |
| **누적 합**           | 전처리 O(n)     | O(n)            | 구간 질의당 O(1)               |
