## 동적 프로그래밍 활용

**UNIT 15(동적 프로그래밍 기초)** 의 후속 단원으로, 코딩 테스트에서 자주 출제되는 대표 DP 유형인 **LIS**, **0/1 배낭 문제**, **편집 거리**, **LCS**를 유형별 점화식 중심으로 정리한다.

<br>

### 1. 유형별 학습 포인트

- DP 문제는 결국 **상태 정의 → 점화식 → 초기값 → 계산 순서**의 틀은 같고, 유형마다 **상태를 무엇으로 정의하는가**가 다름
- 아래 네 유형은 상태 정의의 대표 패턴이므로, 각 유형의 점화식을 유도 과정과 함께 이해하면 변형 문제에 대응할 수 있음

<br>

### 2. LIS(최장 증가 부분 수열)

주어진 수열에서 **원소들이 증가하는 순서를 유지하는 가장 긴 부분 수열**의 길이를 구하는 문제다. 부분 수열은 연속일 필요가 없다.

<br>

### 2-1. O(n²) DP 풀이

**상태 정의**: `dp[i] = i번째 원소를 마지막으로 하는 LIS의 길이`

**점화식**

```
dp[i] = max(dp[j] + 1)   (단, j < i 이고 arr[j] < arr[i])
dp[i] = 1                (조건을 만족하는 j가 없을 때)
```

수열 `[10, 20, 10, 30, 20, 50]`의 계산 결과는 다음과 같다.

```
arr : 10  20  10  30  20  50
dp  :  1   2   1   3   2   4    →  LIS 길이 = 4  (10, 20, 30, 50)
```

<br>

### 2-2. 이진 탐색을 이용한 O(n log n) 개요

- 길이가 `k`인 증가 부분 수열의 **가장 작은 마지막 원소**만 담는 보조 배열을 유지함
- 각 원소에 대해 보조 배열에서 **자신이 들어갈 위치를 이진 탐색**으로 찾아, 배열 끝이면 추가하고 아니면 해당 위치의 값을 교체함
- 원소마다 이진 탐색 O(log n)을 수행하므로 전체 **O(n log n)**

> ⚠️ 이진 탐색 방식에서 보조 배열의 길이는 LIS의 길이와 일치하지만, 보조 배열 자체가 실제 LIS인 것은 아니다. 실제 수열을 복원하려면 각 원소가 놓인 위치를 별도로 기록해야 한다.

<br>

### 3. 0/1 배낭 문제(Knapsack)

무게 제한이 있는 배낭에 물건을 **넣거나(1) 넣지 않거나(0)** 선택해 가치의 합을 최대로 만드는 문제다. 물건을 쪼갤 수 없다는 점에서 그리디로 풀 수 없고 DP가 필요하다.

**상태 정의**: `dp[i][w] = 처음 i개의 물건으로 무게 w 이하를 채울 때 얻는 최대 가치`

**점화식**

```
dp[i][w] = dp[i-1][w]                                  (weight[i] > w, 못 넣는 경우)
dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])   (넣거나 / 안 넣거나)
```

<br>

### 3-1. 2차원 테이블 채우기 예시

물건 3개 — A(무게 1, 가치 6), B(무게 2, 가치 10), C(무게 3, 가치 12), 배낭 용량 `W = 5`.

```
              w=0   w=1   w=2   w=3   w=4   w=5
없음            0     0     0     0     0     0
A(1,6)          0     6     6     6     6     6
B(2,10)         0     6    10    16    16    16
C(3,12)         0     6    10    16    18    22
                                              ↑
                        dp[3][5] = max(dp[2][5], dp[2][2] + 12)
                                 = max(16, 10 + 12) = 22
```

각 칸은 "위 칸(안 넣음)"과 "위 왼쪽 칸 + 가치(넣음)" 중 큰 값으로 채워진다. 최종 답은 **B + C = 가치 22**다.

> 💡 점화식이 `dp[i-1]` 행만 참조하므로 1차원 배열로 압축할 수 있다. 이때는 같은 물건이 중복 선택되지 않도록 무게 `w`를 **큰 쪽에서 작은 쪽으로** 순회해야 한다.

<br>

### 4. 편집 거리(Edit Distance)

문자열 A를 B로 바꾸는 데 필요한 **삽입·삭제·교체 연산의 최소 횟수**를 구하는 문제다.

**상태 정의**: `dp[i][j] = A의 앞 i글자를 B의 앞 j글자로 바꾸는 최소 연산 횟수`

**점화식**

```
dp[i][j] = dp[i-1][j-1]                              (A[i] == B[j], 연산 불필요)
dp[i][j] = min(dp[i-1][j]   + 1,    # 삭제
               dp[i][j-1]   + 1,    # 삽입
               dp[i-1][j-1] + 1)    # 교체          (A[i] != B[j])
```

**초기값**: `dp[i][0] = i`(모두 삭제), `dp[0][j] = j`(모두 삽입)

<br>

### 5. LCS(최장 공통 부분 수열)

두 문자열에서 **순서를 유지하며 공통으로 등장하는 가장 긴 부분 수열**의 길이를 구한다. 편집 거리와 같은 2차원 상태 정의를 쓰는 대표 유형이다.

**점화식**

```
dp[i][j] = dp[i-1][j-1] + 1              (A[i] == B[j])
dp[i][j] = max(dp[i-1][j], dp[i][j-1])   (A[i] != B[j])
```

❗️**LCS와 편집 거리의 관계**: 두 문제 모두 "두 문자열의 앞부분끼리 비교"라는 동일한 상태 정의를 공유하며, 마지막 문자가 같은지에 따라 분기하는 구조도 같다. 한 유형을 이해하면 다른 유형의 점화식도 자연스럽게 유도된다.

<br>

### 6. Python 구현 예시

```python
# 1) LIS — O(n^2) DP
def lis_length(arr):
    n = len(arr)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if arr[j] < arr[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)


# 2) 0/1 배낭 문제 — 2차원 DP
def knapsack(weights, values, W):
    n = len(weights)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]                     # 넣지 않는 경우
            if weights[i - 1] <= w:                     # 넣을 수 있는 경우
                dp[i][w] = max(dp[i][w],
                               dp[i - 1][w - weights[i - 1]] + values[i - 1])
    return dp[n][W]
```

### 7. 유형별 점화식·복잡도 비교

| **유형**        | **상태 정의**                          | **점화식 핵심**                                  | **시간 복잡도**            | **공간 복잡도** |
| --------------- | -------------------------------------- | ------------------------------------------------ | -------------------------- | --------------- |
| **LIS**         | `dp[i]` = i를 끝으로 하는 LIS 길이     | `max(dp[j] + 1)`, `arr[j] < arr[i]`              | **O(n²)** / **O(n log n)** | O(n)            |
| **0/1 배낭**    | `dp[i][w]` = i개·무게 w의 최대 가치    | `max(안 넣음, 넣음)`                             | **O(nW)**                  | O(nW) → O(W)    |
| **편집 거리**   | `dp[i][j]` = 앞 i, j글자 간 최소 연산  | `min(삭제, 삽입, 교체) + 1`                      | **O(nm)**                  | O(nm)           |
| **LCS**         | `dp[i][j]` = 앞 i, j글자의 LCS 길이    | 같으면 `+1`, 다르면 `max`                        | **O(nm)**                  | O(nm)           |

> 💡 배낭 문제의 O(nW)는 입력 "값"의 크기 W에 비례하는 **의사 다항 시간**(Pseudo-polynomial Time)이다. W가 매우 크면 사실상 다항 시간이 아니므로, 문제의 제한 조건을 보고 DP 적용 가능 여부를 판단해야 한다.
