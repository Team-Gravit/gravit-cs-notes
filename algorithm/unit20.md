## 파라메트릭 서치와 lower/upper bound

**파라메트릭 서치(Parametric Search)** 는 최적화 문제를 **결정 문제(예/아니오)** 로 바꾸어 이진 탐색으로 해결하는 기법이고, **lower bound / upper bound**는 정렬된 배열에서 특정 값의 삽입 위치(경계)를 찾는 이진 탐색의 변형이다. 두 기법 모두 이진 탐색(unit19)을 선행 지식으로 한다.

<br>

### 1. 파라메트릭 서치의 개념

"조건을 만족하는 **최댓값(또는 최솟값)** 을 구하라"는 최적화 문제를, "값 x가 조건을 만족하는가?"라는 **결정 문제**로 변환한다. 결정 함수의 답이 어느 지점을 기준으로 **예 → 아니오(또는 아니오 → 예)로 한 번만 바뀌는 단조성**이 있으면, 그 경계를 이진 탐색으로 찾을 수 있다.

<br>

### 2. 이진 탐색과의 차이

| **항목**        | **이진 탐색**                  | **파라메트릭 서치**                       |
| --------------- | ------------------------------ | ----------------------------------------- |
| **탐색 대상**   | 배열 속의 **특정 값**          | 조건을 만족하는 **최적의 답(매개변수)**   |
| **탐색 공간**   | 정렬된 배열의 인덱스           | **답이 될 수 있는 값의 범위**             |
| **판단 기준**   | `arr[mid] == target` 여부      | **결정 함수 check(mid)의 참/거짓**        |
| **종료 결과**   | 값의 위치 또는 실패(-1)        | 조건을 만족하는 **경계값**                |

<br>

### 3. 대표 예제 — 나무 자르기(랜선 자르기 유형)

높이 H로 나무를 자르면 H보다 높은 부분이 잘려 나온다. "잘린 나무 길이의 합이 M 이상이 되는 **최대 H**"를 구하는 문제다. H가 낮을수록 잘린 양이 많아지므로 결정 함수는 단조성을 가진다.

```
나무 높이: [20, 15, 10, 17],  필요량 M = 7

절단 높이 H:   0    5    10   15   16   17   20
잘린 양:       62   42   22   7    5    3    0
M 이상인가?    예   예   예   예  아니오 아니오 아니오
              ─────────────────┬──────────────────
                          경계 = 15  ← "예"인 마지막 지점이 답
```

```python
def cut(trees, h):                 # 결정 함수: 높이 h로 잘랐을 때 얻는 양
    return sum(t - h for t in trees if t > h)

def max_height(trees, m):
    left, right = 0, max(trees)
    answer = 0
    while left <= right:
        mid = (left + right) // 2
        if cut(trees, mid) >= m:   # 조건 만족 → 답 후보, 더 높이 시도
            answer = mid
            left = mid + 1
        else:                      # 부족 → 더 낮게 잘라야 함
            right = mid - 1
    return answer
```

> 💡 파라메트릭 서치 문제는 "답을 고정하면 판정이 쉬워지는가?"와 "판정 결과가 단조적인가?" 두 가지를 먼저 확인해야 한다. 둘 다 성립하면 답의 범위에 대한 이진 탐색으로 해결된다.

<br>

### 4. lower bound / upper bound 정의

정렬된 배열에서 목표 값과 **같은 값이 여러 개** 있을 때, 단순 이진 탐색은 그중 임의의 위치를 반환한다. 경계가 필요할 때는 다음 두 연산을 사용한다.

- **lower bound**: target **이상**(≥)인 값이 처음 나타나는 인덱스
- **upper bound**: target **초과**(>)인 값이 처음 나타나는 인덱스

```
인덱스:  0   1   2   3   4   5   6
값:     [1,  2,  4,  4,  4,  7,  9]        target = 4

lower_bound(4) = 2   ← 4 이상이 처음 나오는 위치
upper_bound(4) = 5   ← 4 초과가 처음 나오는 위치
                 [1,  2, |4,  4,  4,| 7,  9]
                         ↑lb         ↑ub
```

<br>

### 5. 구현

```python
def lower_bound(arr, target):
    left, right = 0, len(arr)          # right는 배열 길이(끝 지점 포함)
    while left < right:
        mid = (left + right) // 2
        if arr[mid] >= target:         # 이상이면 왼쪽으로 좁힘
            right = mid
        else:
            left = mid + 1
    return left

def upper_bound(arr, target):
    left, right = 0, len(arr)
    while left < right:
        mid = (left + right) // 2
        if arr[mid] > target:          # 초과이면 왼쪽으로 좁힘
            right = mid
        else:
            left = mid + 1
    return left
```

❗️**단순 이진 탐색과의 구현 차이**: `while left < right`(등호 없음)와 `right = mid`(mid - 1이 아님)를 사용하며, 값을 찾아도 즉시 반환하지 않고 범위가 한 점으로 수렴할 때까지 계속 좁힌다. 두 함수의 차이는 비교 연산자 **`>=` 와 `>`** 하나뿐이다.

> ⚠️ `right`의 초기값은 `len(arr) - 1`이 아니라 **`len(arr)`** 이다. 모든 원소가 target보다 작으면 삽입 위치가 배열의 끝(len(arr))이 되기 때문이다.

<br>

### 6. 응용 — 중복 원소 개수 세기

정렬된 배열에서 target의 개수는 두 경계의 차로 **O(log n)** 에 구할 수 있다.

```python
arr = [1, 2, 4, 4, 4, 7, 9]
count = upper_bound(arr, 4) - lower_bound(arr, 4)  # 5 - 2 = 3
```

> 💡 Python 표준 라이브러리 `bisect`의 `bisect_left`가 lower bound, `bisect_right`가 upper bound에 해당한다. C++에서는 `std::lower_bound`, `std::upper_bound`를 사용한다.

<br>

### 7. 세 가지 탐색 비교

| **항목**        | **이진 탐색**        | **lower bound**            | **upper bound**            |
| --------------- | -------------------- | -------------------------- | -------------------------- |
| **반환 값**     | 일치하는 값의 인덱스 | target **이상** 첫 위치    | target **초과** 첫 위치    |
| **값이 없을 때** | **-1** (실패)       | 삽입 가능한 위치 반환      | 삽입 가능한 위치 반환      |
| **중복 값 처리** | 임의 위치 반환      | **가장 왼쪽** 경계         | **가장 오른쪽 경계 + 1**   |
| **시간 복잡도** | **O(log n)**         | **O(log n)**               | **O(log n)**               |

<br>
