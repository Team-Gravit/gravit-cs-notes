## 이진 탐색(Binary Search)

**정렬된 배열**에서 탐색 범위를 **절반씩 줄여가며** 목표 값을 찾는 알고리즘이다. 매 단계 비교 한 번으로 후보를 절반으로 줄이므로 **O(log n)** 의 시간 복잡도를 가지며, 코딩테스트에서 가장 빈출되는 탐색 기법이다.

<br>

### 1. 전제 조건

이진 탐색은 배열이 **오름차순(또는 내림차순)으로 정렬**되어 있어야만 동작한다. 정렬되어 있지 않으면 "중간 값과 비교해 한쪽 절반을 버린다"는 논리가 성립하지 않는다.

❗️**정렬 비용 주의**: 정렬되지 않은 배열이라면 정렬에 **O(n log n)** 이 먼저 든다. 탐색을 한 번만 수행한다면 선형 탐색 O(n)이 오히려 유리할 수 있고, 탐색이 여러 번 반복될 때 정렬 + 이진 탐색이 이득이다.

<br>

### 2. 동작 원리

탐색 범위의 **중간 원소(mid)** 와 목표 값을 비교한다.

- `arr[mid] == target` → 탐색 성공
- `arr[mid] < target` → 목표는 오른쪽 절반에 존재 → `left = mid + 1`
- `arr[mid] > target` → 목표는 왼쪽 절반에 존재 → `right = mid - 1`

```
target = 7 탐색

인덱스:  0   1   2   3   4   5   6   7
값:     [1,  3,  5,  7,  9, 11, 13, 15]

[1단계] left=0, right=7, mid=3 → arr[3]=7 ... 비교
        [1,  3,  5, (7),  9, 11, 13, 15]
                     ↑ arr[mid] == target → 성공

target = 11 탐색

[1단계] left=0, right=7, mid=3 → arr[3]=7 < 11 → 오른쪽 절반
        [ x,  x,  x,  x |  9, 11, 13, 15]
[2단계] left=4, right=7, mid=5 → arr[5]=11 == target → 성공
```

매 단계마다 후보 개수가 n → n/2 → n/4 → ... 로 줄어든다.

<br>

### 3. 반복문 구현

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1

    while left <= right:              # 등호 포함 필수
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid                # 찾은 인덱스 반환
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1                         # 탐색 실패
```

<br>

### 4. 재귀 구현

```python
def binary_search_rec(arr, target, left, right):
    if left > right:                  # 기저 조건: 탐색 실패
        return -1

    mid = (left + right) // 2
    if arr[mid] == target:
        return mid
    elif arr[mid] < target:
        return binary_search_rec(arr, target, mid + 1, right)
    else:
        return binary_search_rec(arr, target, left, mid - 1)
```

> 💡 재귀 구현은 분할 정복(unit18)의 구조를 그대로 보여주지만, 반복문 구현이 스택 오버플로 위험이 없고 더 빠르므로 실전에서는 반복문 구현을 권장한다.

<br>

### 5. 경계 조건에서 자주 하는 실수

| **실수**                        | **문제점**                                        | **올바른 방법**                  |
| ------------------------------- | ------------------------------------------------- | -------------------------------- |
| **`while left < right`**        | 원소 1개 남은 구간을 검사하지 못함                | **`left <= right`** 사용         |
| **`left = mid` / `right = mid`** | 범위가 줄지 않아 **무한 루프** 발생 가능         | **`mid + 1` / `mid - 1`** 사용   |
| **`(left + right) / 2` 오버플로** | C/Java에서 int 범위 초과 시 값이 깨짐            | **`left + (right - left) / 2`**  |

> ⚠️ Python은 정수 크기 제한이 없어 `(left + right) // 2` 오버플로가 발생하지 않지만, Java·C++ 등에서는 `int mid = left + (right - left) / 2;` 형태로 작성하는 습관이 필요하다.

<br>

### 6. 시간 복잡도 O(log n) 도출

크기 n인 배열에서 k번 비교하면 남는 후보는 n / 2ᵏ 개다. 후보가 1개가 될 때 탐색이 끝나므로 다음이 성립한다.

```
n / 2^k = 1   →   n = 2^k   →   k = log₂ n
```

| **입력 크기 n** | **최대 비교 횟수 (log₂ n)** |
| --------------- | --------------------------- |
| **1,000**       | 약 **10회**                 |
| **1,000,000**   | 약 **20회**                 |
| **10억**        | 약 **30회**                 |

입력이 백만 배 커져도 비교 횟수는 20회 정도만 늘어난다. 이것이 로그 시간의 위력이다.

<br>

### 7. 선형 탐색과 비교

| **항목**          | **선형 탐색**        | **이진 탐색**              |
| ----------------- | -------------------- | -------------------------- |
| **전제 조건**     | 없음                 | **정렬된 배열**            |
| **시간 복잡도**   | **O(n)**             | **O(log n)**               |
| **구현 난이도**   | 매우 쉬움            | 경계 조건 실수 잦음        |
| **적합한 상황**   | 1회성 탐색, 소규모   | 반복 탐색, 대규모 데이터   |

<br>

### 8. 코딩테스트 활용

- **값의 존재/위치 확인**: 정렬된 배열에서 특정 수 찾기 (백준 1920 「수 찾기」 유형)
- **표준 라이브러리 활용**: Python `bisect` 모듈, Java `Arrays.binarySearch()`
- **답의 범위를 탐색**: 정답이 될 수 있는 값의 구간에서 조건을 만족하는 최적값을 찾는 **파라메트릭 서치(unit20)** 로 확장
- **분할 정복과의 연결**: 탐색 범위를 절반으로 줄이는 구조는 분할 정복(unit18)에서 한쪽 부분 문제만 남기는 특수 형태다

```python
from bisect import bisect_left

arr = [1, 3, 5, 7, 9]
idx = bisect_left(arr, 5)   # 2 — 5가 들어갈 가장 왼쪽 위치
```

> 💡 `n ≤ 10⁵` 규모에서 탐색 쿼리가 많이 주어지는 문제, 또는 "최대 중의 최소 / 최소 중의 최대"를 묻는 문제가 보이면 이진 탐색 계열을 먼저 의심하는 것이 좋다.
