## 문자열 탐색 — KMP

**KMP(Knuth-Morris-Pratt) 알고리즘**은 텍스트에서 패턴 문자열을 찾을 때, 이미 일치했던 정보를 **실패 함수(부분 일치 테이블)** 에 저장해 두고 재활용하여 **O(n+m)** 에 탐색을 끝내는 알고리즘이다. 브루트 포스 탐색의 중복 비교를 제거하는 것이 핵심이다.

<br>

### 1. 브루트 포스 문자열 탐색의 비효율

가장 단순한 방법은 텍스트의 모든 시작 위치에서 패턴을 처음부터 끝까지 비교하는 것이다. 텍스트 길이 `n`, 패턴 길이 `m`일 때 최악 **O(nm)** 이다.

```
텍스트: A A A A A B      패턴: A A A B

A A A A A B
A A A B          ← 3글자 일치 후 4번째에서 불일치

A A A A A B
  A A A B        ← 한 칸만 밀고 처음부터 다시 비교 (앞의 일치 정보 버림)

A A A A A B
    A A A B      ← 또 처음부터 비교 → 일치 발견
```

시작 위치를 한 칸 밀 때마다 **이미 일치를 확인한 문자들을 처음부터 다시 비교**한다. 반복 패턴이 많은 문자열일수록 이 낭비가 커진다.

> ⚠️ 브루트 포스의 최악 사례는 `"AAAA...A"`에서 `"AA...AB"`를 찾는 것처럼 **거의 일치하다가 마지막에 어긋나는** 입력이다. 이 경우 매 시작 위치마다 m번 가까이 비교하여 정확히 O(nm)이 된다.

<br>

### 2. 접두사와 접미사

KMP를 이해하려면 문자열의 **접두사(Prefix)** 와 **접미사(Suffix)** 개념이 필요하다.

- **접두사**: 문자열의 앞에서부터 자른 부분 문자열 — `"ABAB"`의 접두사: `A`, `AB`, `ABA`, `ABAB`
- **접미사**: 문자열의 뒤에서부터 자른 부분 문자열 — `"ABAB"`의 접미사: `B`, `AB`, `BAB`, `ABAB`
- 이 중 문자열 전체를 제외한 것을 **진접두사·진접미사**라 하며, KMP는 **접두사이면서 동시에 접미사인 부분**의 최대 길이를 이용함

```
"ABAB" 에서 접두사 == 접미사가 되는 경우

접두사: A B | . .        접미사: . . | A B
        ─────                    ─────
        "AB"       ==           "AB"    → 최대 일치 길이 2
```

<br>

### 3. 실패 함수(부분 일치 테이블)

**실패 함수** `failure[i]`는 패턴의 `0 ~ i`번째 글자까지의 부분 문자열에서, **접두사와 접미사가 일치하는 최대 길이**(전체 제외)로 정의한다.

패턴 `"ABABC"`의 실패 함수를 단계별로 구하면 다음과 같다.

```
i   부분 문자열   접두사 == 접미사 후보          failure[i]
─   ──────────   ──────────────────────────     ──────────
0   A            (길이 1은 전체뿐이므로 없음)        0
1   AB           A / B                → 불일치       0
2   ABA          A / A                → 일치(길이1)  1
3   ABAB         AB / AB              → 일치(길이2)  2
4   ABABC        C로 끝나 일치 없음                  0

패턴    : A  B  A  B  C
failure : 0  0  1  2  0
```

`failure[i] = k`의 의미: **i번째 글자에서 불일치가 나면, 패턴의 k번째 글자부터 비교를 이어가도 된다**(앞의 k글자는 이미 일치가 보장됨).

<br>

### 4. KMP 탐색 과정

텍스트 `"ABABABC"`에서 패턴 `"ABABC"`를 찾는 과정이다. 불일치가 발생해도 텍스트 포인터는 뒤로 가지 않고, **패턴 포인터만 실패 함수를 따라 이동**한다.

```
텍스트  : A B A B A B C          패턴: A B A B C  (failure: 0 0 1 2 0)

단계 1
A B A B A B C
A B A B C            텍스트[4]='A' vs 패턴[4]='C' → 불일치
        ↑             일치 길이 4 → failure[3] = 2 만큼 되돌아감

단계 2  (패턴을 2칸 민 효과, 텍스트 포인터는 그대로)
A B A B A B C
    A B A B C        패턴[2]='A'부터 비교 재개
        ↑             텍스트[4]='A' vs 패턴[2]='A' → 일치, 계속 진행

단계 3
A B A B A B C
    A B A B C        텍스트[5]='B', [6]='C' 까지 모두 일치
            ↑         → 인덱스 2에서 패턴 발견
```

브루트 포스라면 단계 1과 단계 2 사이에 패턴을 한 칸씩 밀며 헛된 비교를 했겠지만, KMP는 실패 함수 덕분에 **안전하게 두 칸을 건너뛰고** 이미 일치한 `"AB"`는 다시 비교하지 않는다.

> 💡 텍스트 포인터가 절대 뒤로 이동하지 않으므로 텍스트 비교는 최대 2n번, 실패 함수 계산도 같은 원리로 최대 2m번 안에 끝난다. 그래서 전체 복잡도가 O(n+m)이 된다.

<br>

### 5. Python 구현

```python
def build_failure(pattern):
    m = len(pattern)
    failure = [0] * m
    k = 0                                # 현재까지 일치한 접두사 길이
    for i in range(1, m):
        while k > 0 and pattern[i] != pattern[k]:
            k = failure[k - 1]           # 일치가 깨지면 더 짧은 접두사로 후퇴
        if pattern[i] == pattern[k]:
            k += 1
        failure[i] = k
    return failure


def kmp_search(text, pattern):
    n, m = len(text), len(pattern)
    failure = build_failure(pattern)
    result = []
    j = 0                                # 패턴 포인터
    for i in range(n):                   # 텍스트 포인터는 전진만 함
        while j > 0 and text[i] != pattern[j]:
            j = failure[j - 1]           # 불일치 → 실패 함수로 점프
        if text[i] == pattern[j]:
            j += 1
            if j == m:                   # 패턴 전체 일치
                result.append(i - m + 1)
                j = failure[j - 1]       # 겹치는 다음 일치도 탐색
    return result


print(kmp_search("ABABABC", "ABABC"))    # [2]
```

❗️**실패 함수 계산의 핵심**: `build_failure`는 패턴을 자기 자신과 비교하는 KMP 탐색과 같은 구조다. 불일치 시 `k = failure[k-1]`로 후퇴하는 while문을 빠뜨리면 잘못된 테이블이 만들어진다.

<br>

### 6. 시간·공간 복잡도

| **단계**             | **시간 복잡도** | **공간 복잡도** | **설명**                          |
| -------------------- | --------------- | --------------- | --------------------------------- |
| **실패 함수 계산**   | O(m)            | O(m)            | 패턴을 자기 자신과 비교           |
| **텍스트 탐색**      | O(n)            | O(1)            | 텍스트 포인터는 전진만 함         |
| **전체**             | **O(n+m)**      | **O(m)**        | 입력 크기에 선형                  |

<br>

### 7. 브루트 포스 vs KMP 비교

| **항목**             | **브루트 포스**                | **KMP**                              |
| -------------------- | ------------------------------ | ------------------------------------ |
| **시간 복잡도**      | 최악 **O(nm)**                 | **O(n+m)**                           |
| **추가 공간**        | O(1)                           | O(m) (실패 함수 테이블)              |
| **불일치 시 동작**   | 시작 위치를 **한 칸** 밀고 재비교 | 실패 함수만큼 **건너뛰고** 이어서 비교 |
| **텍스트 포인터**    | 뒤로 되돌아감                  | **전진만** 함                        |
| **전처리**           | 없음                           | 실패 함수 계산 필요                  |
| **유리한 상황**      | 짧은 패턴, 일회성 탐색         | 반복 패턴이 많은 긴 문자열           |

> 💡 실무의 문자열 검색 함수가 항상 KMP를 쓰는 것은 아니다. 평균적으로는 브루트 포스도 빠르게 끝나는 경우가 많아, 언어 표준 라이브러리는 입력 특성에 따라 여러 알고리즘을 조합해 사용한다. KMP의 가치는 **최악의 경우에도 선형 시간을 보장**한다는 점에 있다.
