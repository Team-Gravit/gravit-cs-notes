## 가변·불변 객체와 함정

파이썬의 모든 값은 객체이며, 생성 후 내용을 바꿀 수 있는 **가변(Mutable) 객체**와 바꿀 수 없는 **불변(Immutable) 객체**로 나뉜다. 이 구분을 모르면 "함수 인자로 넘긴 리스트가 왜 바뀌었는지", "기본 인자 값이 왜 호출마다 누적되는지", "복사했는데 왜 원본이 변하는지" 같은 실무 버그를 이해할 수 없다.

<br>

### 1. 가변 객체와 불변 객체

| **구분**       | **타입**                                            | **내용 변경**                    | **해시 가능**            |
| -------------- | --------------------------------------------------- | -------------------------------- | ------------------------ |
| **불변**       | `int`, `float`, `str`, `tuple`, `frozenset`, `bytes` | 불가 — 연산 결과는 **새 객체**   | **가능** (dict 키·set 원소) |
| **가변**       | `list`, `dict`, `set`, `bytearray`, 사용자 정의 클래스 | 가능 — **같은 객체**를 제자리 수정 | 기본적으로 불가          |

```python
s = "abc"
print(id(s))
s += "d"           # 새 문자열 객체 생성 → id가 바뀜
print(id(s))

lst = [1, 2]
print(id(lst))
lst += [3]         # 같은 리스트를 제자리(in-place) 수정 → id 동일
print(id(lst))
```

> 💡 `+=`는 가변 객체에서는 `__iadd__`(제자리 수정), 불변 객체에서는 `__add__` 후 재할당으로 동작한다. 같은 연산자가 타입에 따라 "수정"과 "재생성"으로 갈리는 것이 파이썬 함정의 출발점이다.

❗️**튜플도 완전히 불변은 아니다**: `t = ([1], 2)`에서 `t[0].append(9)`는 성공한다. 튜플이 고정하는 것은 "어떤 객체를 가리키는가"이지 그 객체의 내용이 아니다. 가변 원소를 담은 튜플은 해시도 불가능하다.

<br>

### 2. 인자 전달 방식 — 객체 참조에 의한 전달

파이썬은 값 전달(Call by Value)도 참조 전달(Call by Reference)도 아닌 **객체 참조 전달(Call by Object Reference, 또는 Call by Sharing)** 방식이다. 함수는 호출자가 가리키는 **같은 객체**를 받으며, 그 객체가 가변이면 함수 안의 수정이 호출자에게 보인다.

```
호출자                      함수 내부
name ──┐                    param ──┐
       ▼                            ▼
   ┌────────────┐  같은 객체를 공유  ┌────────────┐
   │  [1, 2, 3] │ ◀────────────── │  (동일 객체) │
   └────────────┘                  └────────────┘
param.append(4)  → 호출자의 name도 [1, 2, 3, 4]
param = [9]      → 이름표만 새 객체로 옮김, 호출자는 영향 없음
```

```python
def add_item(items, x):
    items.append(x)        # 호출자의 리스트를 직접 수정 (부수 효과)
    return items

def rebind(items):
    items = [0]            # 지역 이름을 새 객체에 다시 바인딩할 뿐
    return items

data = [1, 2]
add_item(data, 3); print(data)   # [1, 2, 3]  — 바뀜
rebind(data);      print(data)   # [1, 2, 3]  — 안 바뀜
```

- **수정(mutation)**과 **재바인딩(rebinding)**을 구분하는 것이 핵심임
- 함수가 인자를 수정하는지 새 객체를 반환하는지 API 관례로 통일함 (`list.sort()`는 제자리 수정 후 `None` 반환, `sorted()`는 새 리스트 반환)

<br>

### 3. 가변 기본 인자(Mutable Default Argument)

파이썬 면접 단골 문제다. **기본 인자 값은 함수가 정의될 때 딱 한 번 평가**되어 함수 객체에 저장되고, 이후 모든 호출이 그 객체를 공유한다.

```python
def append_to(x, items=[]):        # 안티패턴: 기본값 리스트가 정의 시점에 1개만 생성됨
    items.append(x)
    return items

print(append_to(1))    # [1]
print(append_to(2))    # [1, 2]   ← 이전 호출의 값이 남아 있음
print(append_to.__defaults__)      # ([1, 2],)  — 함수 객체에 저장된 기본값
```

```python
def append_to(x, items=None):      # 개선: 감시값(sentinel) None을 쓰고 호출마다 새로 생성
    if items is None:
        items = []
    items.append(x)
    return items

print(append_to(1))    # [1]
print(append_to(2))    # [2]
```

```
def 문 실행 시점                      호출 시점
┌──────────────────────┐            append_to(1) ─┐
│ 함수 객체 생성        │                          ├─▶ 같은 [] 객체를 공유
│ __defaults__ = ([],) │ ◀────────  append_to(2) ─┘
└──────────────────────┘
```

> ⚠️ `dict`, `set`, 사용자 정의 객체, `datetime.now()`처럼 **호출 시마다 새로 평가되길 기대하는 값**은 모두 같은 함정에 빠진다. 기본값에는 불변 객체(`None`, 숫자, 문자열, 튜플)만 두는 것을 습관화한다. 반대로 이 성질을 이용해 함수 정의 시점의 값을 클로저 없이 고정하는 기법(`lambda i=i: ...`)도 있다.

### 4. 얕은 복사와 깊은 복사

`b = a`는 복사가 아니라 **같은 객체에 이름을 하나 더 붙이는 것**이다. 복사가 필요하면 얕은 복사·깊은 복사 중 하나를 명시적으로 선택해야 한다.

<br>

### 4-1. 얕은 복사(Shallow Copy)

새 컨테이너를 만들되 **내부 원소는 원본과 같은 객체를 공유**한다. `list(a)`, `a[:]`, `a.copy()`, `dict(d)`, `copy.copy()`가 모두 얕은 복사다.

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)           # 또는 a[:] / list(a) / a.copy()

b.append([5, 6])           # 바깥 리스트는 별개 → a에 영향 없음
b[0].append(99)            # 안쪽 리스트는 공유 → a[0]도 바뀜
print(a)                   # [[1, 2, 99], [3, 4]]
```

```
얕은 복사
a ──▶ [ ● , ● ]            b ──▶ [ ● , ● ]
        │   │                      │   │
        ▼   ▼                      │   │
      [1,2] [3,4] ◀────────────────┘   │   ← 안쪽 객체는 공유
        ▲                              │
        └──────────────────────────────┘
```

<br>

### 4-2. 깊은 복사(Deep Copy)

`copy.deepcopy()`는 컨테이너를 **재귀적으로 따라가며 모든 가변 객체를 새로 만든다**. 순환 참조가 있어도 이미 복사한 객체를 메모(memo) 딕셔너리로 기억해 무한 재귀에 빠지지 않는다.

```python
import copy

a = [[1, 2], [3, 4]]
c = copy.deepcopy(a)
c[0].append(99)
print(a)                   # [[1, 2], [3, 4]] — 완전히 독립

class Config:
    def __deepcopy__(self, memo):          # 복사 방식을 직접 제어
        new = Config.__new__(Config)
        memo[id(self)] = new
        new.settings = copy.deepcopy(self.settings, memo)
        new.conn = self.conn               # 소켓 같은 자원은 공유
        return new
```

| **항목**            | **할당 (`b = a`)**  | **얕은 복사**                  | **깊은 복사**                    |
| ------------------- | ------------------- | ------------------------------ | -------------------------------- |
| **새 객체 생성**    | 없음                | **바깥 컨테이너만**            | **모든 계층**                    |
| **내부 원소**       | 공유                | 공유                           | 독립                             |
| **비용**            | O(1)                | O(n)                           | O(전체 객체 수), 가장 큼         |
| **적합한 상황**     | 별칭이 필요할 때    | 1차원 컨테이너, 원소가 불변일 때 | 중첩 구조를 독립적으로 수정할 때 |

> ⚠️ `[[0] * 3] * 3`으로 2차원 리스트를 만들면 안쪽 리스트 하나가 3번 공유된다. `grid[0][0] = 1`을 하면 모든 행의 첫 열이 1이 된다. 반드시 `[[0] * 3 for _ in range(3)]`처럼 컴프리헨션으로 행마다 새 리스트를 만들어야 한다. 알고리즘 문제에서 가장 자주 나오는 실수다.

### 5. 해시 가능성과 딕셔너리 키

`dict`의 키와 `set`의 원소는 **해시 가능(hashable)**해야 한다. 해시 값은 객체가 살아 있는 동안 변하지 않아야 하므로 가변 객체는 기본적으로 해시가 불가능하다.

```python
d = {}
d[(1, 2)] = "ok"           # 튜플은 불변 → 키 가능
d[[1, 2]] = "error"        # TypeError: unhashable type: 'list'
d[frozenset({1, 2})] = "ok"

from dataclasses import dataclass

@dataclass(frozen=True)    # 필드 변경 금지 + __hash__ 자동 생성
class Point:
    x: int
    y: int

visited = {Point(0, 0)}    # set 원소로 사용 가능
```

- 사용자 정의 클래스는 기본적으로 **id 기반 해시**를 가지지만, `__eq__`를 재정의하면 `__hash__`가 `None`이 되어 해시 불가가 됨 (unit06 참고)
- 좌표·상태를 `set`으로 방문 체크할 때 리스트 대신 튜플을 쓰는 이유가 바로 이것임

<br>

### 6. 불변성을 활용하는 설계

- **함수는 인자를 수정하지 말고 새 값을 반환**하면 호출자에게 부수 효과가 없어 추론과 테스트가 쉬움
- 클래스 상수, 설정값은 `tuple`·`frozenset`·`frozen dataclass`·`typing.Final`로 선언해 실수로 수정되는 것을 막음
- 문자열은 불변이므로 반복문에서 `s += ...`로 이어 붙이면 매번 새 객체를 만든다. 대량 결합은 리스트에 모아 `"".join()`을 사용함
- 딕셔너리를 순회하면서 키를 추가·삭제하면 `RuntimeError`가 발생한다. `list(d.keys())`로 스냅샷을 만들어 순회하거나 새 딕셔너리를 만듦

```python
def total_len(words):
    return sum(len(w) for w in words)         # 인자를 건드리지 않는 순수 함수

parts = []
for i in range(10_000):
    parts.append(str(i))
text = "".join(parts)                         # 반복 += 보다 훨씬 빠름
```

### 7. 면접·실무 체크포인트

| **질문**                                              | **핵심 답변**                                                                          |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **파이썬은 값 전달인가 참조 전달인가?**               | 객체 참조 전달. 가변 객체는 함수 안 수정이 밖에 보이고, 재바인딩은 보이지 않음            |
| **기본 인자로 `[]`를 쓰면 왜 문제인가?**              | 기본값은 정의 시 한 번만 평가되어 모든 호출이 공유. `None` 감시값으로 대체                |
| **얕은 복사와 깊은 복사 차이는?**                     | 얕은 복사는 바깥만 새로 만들고 내부 공유, 깊은 복사는 재귀적으로 전부 새로 생성            |
| **`[[0]*3]*3`이 왜 잘못인가?**                        | 같은 안쪽 리스트를 3번 참조. 컴프리헨션으로 행마다 생성                                  |
| **리스트는 왜 dict 키가 될 수 없나?**                 | 가변이라 해시가 바뀔 수 있음. 튜플·frozenset·frozen dataclass 사용                         |
| **튜플은 완전히 불변인가?**                           | 참조 목록만 고정. 가변 원소의 내용은 바뀔 수 있음                                         |
| **`a is b`와 `a == b`의 차이는?**                     | `is`는 같은 객체인지(id), `==`는 값이 같은지. 작은 정수 캐싱 때문에 `is` 결과가 달라질 수 있음(unit02 참고) |
