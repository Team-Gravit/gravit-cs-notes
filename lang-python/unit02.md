## 메모리 관리

CPython은 **레퍼런스 카운팅(Reference Counting, 참조 횟수 계산)**을 기본으로 하고, 이것만으로 회수하지 못하는 **순환 참조(Reference Cycle)**를 세대별 가비지 컬렉터(Generational GC)가 보조적으로 수집한다. 두 메커니즘의 역할 분담을 이해해야 메모리 누수의 원인을 찾고 `__del__`·`weakref`·`gc` 모듈을 올바르게 다룰 수 있다.

<br>

### 1. 모든 것은 객체, 변수는 이름표

파이썬의 변수는 값을 담는 상자가 아니라 **힙에 있는 객체를 가리키는 이름(참조)**이다. 모든 객체는 C 구조체 `PyObject`로 표현되며, 머리 부분에 두 가지 정보를 항상 가진다.

```
PyObject 헤더
┌────────────────────┬─────────────────┬──────────────┐
│ ob_refcnt (참조 수) │ ob_type (타입)   │ 실제 데이터   │
└────────────────────┴─────────────────┴──────────────┘

a = [1, 2, 3]      →  list 객체 ob_refcnt = 1  (a)
b = a              →  list 객체 ob_refcnt = 2  (a, b)
del a              →  list 객체 ob_refcnt = 1  (b)
b = None           →  list 객체 ob_refcnt = 0  → 즉시 해제
```

```python
import sys

a = [1, 2, 3]
print(sys.getrefcount(a))   # 2  (a 자체 + getrefcount 인자로 전달된 임시 참조)
b = a
print(sys.getrefcount(a))   # 3
del b
print(sys.getrefcount(a))   # 2
```

> 💡 `sys.getrefcount()`는 함수 인자로 넘어가는 순간 참조가 하나 늘어나므로 항상 **실제보다 1 크게** 나온다. 면접에서 "왜 2가 나오나요?"를 설명할 수 있으면 참조 개념을 제대로 이해한 것이다.

### 2. 레퍼런스 카운팅

### 2-1. 동작 원리

참조 수는 다음 상황에서 증가하고, 반대 상황에서 감소한다.

| **증가하는 경우**                     | **감소하는 경우**                        |
| ------------------------------------- | ---------------------------------------- |
| 변수에 할당 (`b = a`)                 | 변수 재할당·`del`                        |
| 컨테이너에 담김 (`lst.append(a)`)     | 컨테이너에서 제거·컨테이너 자체 해제      |
| 함수 인자로 전달                      | 함수 반환 (지역 변수 소멸)                |
| 속성으로 저장 (`obj.x = a`)           | 속성 삭제·소유 객체 해제                  |

참조 수가 **0이 되는 즉시** 메모리가 해제되며, 그 객체가 참조하던 다른 객체들의 참조 수도 연쇄적으로 감소한다.

- **장점**: 해제 시점이 결정적(deterministic)이라 파일·소켓 같은 자원이 참조를 잃는 즉시 정리됨. 프로그램 실행 중 긴 멈춤(Stop-the-World)이 없음
- **단점**: 증감 연산이 모든 곳에서 일어나 오버헤드가 있고, 멀티스레드에서 이 연산을 보호하려고 GIL이 필요함(unit01 참고). 그리고 **순환 참조를 회수하지 못함**

<br>

### 2-2. 순환 참조 문제

두 객체가 서로를 참조하면 외부에서 접근 경로가 끊겨도 참조 수가 0이 되지 않는다.

```
x = Node(); y = Node(); x.other = y; y.other = x; del x, y

     ┌──────────┐  other  ┌──────────┐
     │  Node x  │ ──────▶ │  Node y  │
     │ refcnt=1 │ ◀────── │ refcnt=1 │
     └──────────┘  other  └──────────┘
  외부 이름은 모두 사라졌지만 서로 붙잡고 있어 refcnt가 0이 되지 않음 → 누수
```

```python
class Node:
    def __init__(self):
        self.other = None

x, y = Node(), Node()
x.other, y.other = y, x
del x, y                     # 레퍼런스 카운팅만으로는 해제되지 않음
```

### 3. 세대별 가비지 컬렉터 — 순환 참조 수집

CPython의 `gc` 모듈은 순환 참조를 **찾아서** 끊어주는 보조 수집기다. 정수·문자열처럼 다른 객체를 참조할 수 없는 타입은 추적 대상이 아니며, list·dict·사용자 정의 클래스 인스턴스 등 **컨테이너 객체만 추적**한다.

**순환 탐지 알고리즘 (개념)**

1. 추적 중인 컨테이너 객체의 참조 수를 `gc_refs`로 복사함
2. 각 객체가 참조하는 다른 추적 객체의 `gc_refs`를 1씩 감소시킴 — 컨테이너 내부에서 오는 참조를 상쇄
3. 남은 `gc_refs > 0`인 객체는 **외부에서 도달 가능**하므로 살아 있음. 거기서 도달 가능한 객체도 살아 있음
4. 나머지(`gc_refs == 0`이고 외부에서 도달 불가)는 순환 쓰레기 → 해제

**세대(Generation)**

| **세대**     | **대상**                            | **수집 빈도**  | **임계값(기본)**                    |
| ------------ | ----------------------------------- | -------------- | ----------------------------------- |
| **0세대**    | 새로 생성된 객체                    | **가장 잦음**  | 할당 − 해제 수가 **2000** 초과 시 (3.12까지는 700) |
| **1세대**    | 0세대 수집에서 살아남은 객체        | 보통           | 0세대 수집 **10**회마다             |
| **2세대**    | 1세대 수집에서 살아남은 객체        | 가장 드묾      | 1세대 수집 **10**회마다 (추가 조건 있음) |

"오래 살아남은 객체는 계속 살아남을 가능성이 높다"는 **세대 가설**에 따라 젊은 객체를 자주, 늙은 객체를 드물게 검사해 비용을 줄인다.

```python
import gc

print(gc.get_threshold())     # (2000, 10, 10) — 3.13 기준, 3.12까지는 (700, 10, 10)
print(gc.get_count())         # 세대별 현재 카운트
collected = gc.collect()      # 수동으로 전체 수집, 회수한 객체 수 반환
```

> ⚠️ `gc.disable()`로 수집기를 끄면 순환 참조가 쌓여 장시간 실행되는 서버에서 메모리가 계속 늘어난다. 배치 작업에서 대량 객체를 만들 때 일시적으로 끄고 끝나면 `gc.collect()`를 호출하는 식으로만 제한적으로 사용한다. 3세대 구조는 3.12·3.13 기준이며, 3.14부터는 긴 멈춤을 줄이기 위해 **증분(incremental) 수집 방식**으로 바뀌어 세대 구성과 임계값 의미가 달라지므로 버전별 문서를 확인해야 한다.

### 4. `__del__`과 소멸 시점의 함정

- `__del__`(파이널라이저)은 참조 수가 0이 되거나 GC가 회수할 때 호출됨
- 호출 **시점을 신뢰하면 안 됨**: 순환 참조에 얽히면 언제 호출될지 알 수 없고, 인터프리터 종료 중에는 모듈 전역이 이미 `None`이 되어 오류가 날 수 있음
- 3.4(PEP 442) 이후 `__del__`이 있는 객체도 순환 수집이 가능하지만, 자원 해제는 `__del__`이 아니라 **컨텍스트 매니저(`with`)**에 맡기는 것이 원칙임(unit08 참고)

```python
class Conn:                    # 안티패턴: 소멸자에 의존한 자원 해제
    def __init__(self):
        self.sock = open_socket()
    def __del__(self):
        self.sock.close()      # 언제 호출될지 보장되지 않음

class Conn:                    # 개선: 컨텍스트 매니저로 해제 시점을 명시
    def __enter__(self):
        self.sock = open_socket()
        return self
    def __exit__(self, *exc):
        self.sock.close()      # with 블록을 벗어나는 즉시 확실히 호출
```

### 5. 약한 참조(weakref) — 순환을 만들지 않고 참조하기

**약한 참조(Weak Reference)**는 참조 수를 올리지 않는 참조다. 캐시, 부모→자식·자식→부모 양방향 링크, 옵저버 패턴처럼 "있으면 쓰고 없으면 말고" 관계에 적합하다.

```python
import weakref

class Parent:
    def __init__(self):
        self.children = []

class Child:
    def __init__(self, parent):
        self._parent = weakref.ref(parent)   # 강한 순환 대신 약한 참조
        parent.children.append(self)

    @property
    def parent(self):
        return self._parent()                # 살아 있으면 객체, 아니면 None

p = Parent(); c = Child(p)
del p
print(c.parent)                              # None — 부모는 즉시 해제됨
```

- `weakref.WeakValueDictionary`·`WeakKeyDictionary`는 값(또는 키)이 해제되면 항목이 자동으로 사라지는 캐시용 딕셔너리임
- `int`·`str`·`tuple`·`list`·`dict` 등 일부 내장 타입은 약한 참조를 지원하지 않음(서브클래스는 가능)

### 6. 메모리 할당과 최적화 기법

CPython은 작은 객체(512바이트 이하)를 **pymalloc**이라는 전용 할당기로 관리해 `malloc` 호출을 줄이고, 그 위에서 몇 가지 최적화를 수행한다.

| **기법**                | **내용**                                                      | **확인 방법**                       |
| ----------------------- | ------------------------------------------------------------- | ----------------------------------- |
| **작은 정수 캐싱**      | **-5 ~ 256** 정수는 인터프리터 시작 시 미리 생성해 공유         | `a = 100; b = 100; a is b` → `True` |
| **문자열 인터닝**       | 식별자로 쓸 만한 짧은 문자열을 하나의 객체로 공유               | `sys.intern()`으로 명시 가능        |
| **불변 객체 공유**      | 빈 튜플 `()`, `None`, `True`처럼 단일 인스턴스 재사용           | `() is ()` → `True`                 |
| **불멸 객체(3.12)**     | PEP 683 — `None`·작은 정수 등의 참조 수를 아예 갱신하지 않음    | `sys.getrefcount(None)`이 매우 큰 값 |

❗️**`is`로 값을 비교하지 말 것**: `a = 1000; b = 1000; a is b`는 실행 방식(같은 코드 블록에서 상수 폴딩 여부)에 따라 결과가 달라진다. 값 비교는 항상 `==`, `is`는 `None`·싱글턴 확인에만 쓴다.

```python
import tracemalloc

tracemalloc.start()
data = [str(i) * 10 for i in range(100_000)]
current, peak = tracemalloc.get_traced_memory()
print(f"현재 {current / 1e6:.1f}MB, 최고 {peak / 1e6:.1f}MB")
for stat in tracemalloc.take_snapshot().statistics("lineno")[:3]:
    print(stat)                     # 어느 줄에서 얼마나 할당했는지 추적
```

> 💡 `__slots__`를 선언하면 인스턴스마다 생성되는 `__dict__`가 사라져 객체 하나당 메모리가 크게 줄고 속성 접근도 약간 빨라진다. 수백만 개의 작은 객체를 만드는 상황에서 유효한 기법이며 unit06에서 자세히 다룬다.

### 7. 정리

| **질문**                                          | **핵심 답변**                                                                    |
| ------------------------------------------------- | -------------------------------------------------------------------------------- |
| **파이썬은 메모리를 어떻게 관리하나요?**          | 레퍼런스 카운팅이 기본, 순환 참조는 세대별 GC가 보조 수집                          |
| **레퍼런스 카운팅의 한계는?**                     | 순환 참조를 회수하지 못하고, 증감 연산 보호를 위해 GIL이 필요함                     |
| **GC는 어떤 객체를 추적하나요?**                  | 다른 객체를 참조할 수 있는 **컨테이너 객체만** (int·str은 제외)                     |
| **세대별 수집이란?**                              | 0→1→2세대로 승격시키며 젊은 세대를 자주 검사. 기본 임계값 (2000, 10, 10), 3.12까지 700 |
| **`__del__`에서 자원을 닫아도 되나요?**           | 호출 시점이 보장되지 않으므로 `with`(컨텍스트 매니저)를 사용해야 함                 |
| **순환 참조를 예방하려면?**                       | 양방향 링크의 한쪽을 `weakref`로, 캐시는 `WeakValueDictionary`로                    |
| **메모리 누수를 찾는 방법은?**                    | `tracemalloc` 스냅샷 비교, `gc.get_objects()`·`gc.garbage` 점검, `objgraph` 등 도구 |

- 스레드와 GIL이 레퍼런스 카운팅과 얽히는 배경은 **unit01**, `with` 문의 동작은 **unit08**을 참고할 것
