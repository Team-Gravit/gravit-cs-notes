## 유니온-파인드(Union-Find)

**서로소 집합**(Disjoint Set)을 표현하는 자료구조로, 여러 원소가 **같은 집합에 속하는지**를 빠르게 판별하고 두 집합을 **하나로 합치는** 연산을 지원한다. **크루스칼 MST**와 **사이클 판별**의 핵심 자료구조다.

<br>

### 1. 서로소 집합(Disjoint Set)

**서로소 집합**은 **공통 원소가 없는** 집합들을 말한다. 유니온-파인드는 전체 원소를 여러 개의 서로소 집합으로 나누어 관리하며, 다음 두 연산을 제공한다.

- **Find**: 원소가 속한 집합의 **대표(루트) 노드**를 찾는 연산
- **Union**: 두 원소가 속한 집합을 **하나로 합치는** 연산

<br>

### 2. 대표(루트) 노드

각 집합은 **트리** 형태로 표현하며, 트리의 **루트 노드**가 그 집합의 **대표**가 된다. 두 원소의 루트가 같으면 **같은 집합**, 다르면 **서로 다른 집합**에 속한 것이다.

- 각 노드는 **부모 노드의 번호**만 기억한다 (parent 배열)
- 루트 노드는 **자기 자신을 부모로** 가진다 (`parent[x] == x`)

<br>

### 3. Find와 Union의 동작 원리

**Find**는 부모를 따라 올라가며 루트에 도달할 때까지 반복한다. **Union**은 두 원소의 루트를 각각 찾은 뒤, **한쪽 루트를 다른 쪽 루트의 자식**으로 붙인다.

```
Union(4, 6) 수행 과정

  집합 A          집합 B              합쳐진 집합
    1               5                    1
   / \              |         →         /|\
  2   3             6                  2 3 5
      |                                  |  \
      4                                  4   6

  Find(4) = 1, Find(6) = 5  →  parent[5] = 1
```

루트끼리 연결하므로 집합에 속한 모든 원소를 옮길 필요 없이 **부모 배열 값 하나만 수정**하면 된다.

<br>

### 4. 배열 기반 구현

```python
parent = list(range(n + 1))  # 초기화: 자기 자신이 루트

def find(x):
    while parent[x] != x:    # 루트에 도달할 때까지 상향 이동
        x = parent[x]
    return x

def union(a, b):
    root_a, root_b = find(a), find(b)
    if root_a != root_b:
        parent[root_b] = root_a  # 루트끼리 연결
```

<br>

### 5. 편향 트리 문제

최적화 없이 Union을 반복하면 트리가 **한쪽으로 길게 늘어진 편향 트리**가 될 수 있다. 이 경우 Find가 루트까지 **모든 노드를 거쳐야** 하므로 시간 복잡도가 **O(n)** 으로 악화된다.

```
Union(1,2), Union(2,3), Union(3,4) 를 잘못 연결한 경우

  4
  |
  3        → Find(1)은 4 → 3 → 2 → 1 경로를
  |          모두 거슬러 올라가야 함 (O(n))
  2
  |
  1
```

> ⚠️ 최적화 없는 유니온-파인드는 연결 리스트와 다를 바 없는 성능을 보인다. 코딩 테스트에서 시간 초과의 대표적인 원인이므로 **경로 압축은 반드시 함께 구현**해야 한다.

<br>

### 6. 최적화 1 — 경로 압축(Path Compression)

Find를 수행하면서 경로 위의 **모든 노드가 루트를 직접 가리키도록** 부모를 갱신한다. 다음 Find부터는 루트에 **한 번에** 도달할 수 있다.

```python
def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])  # 루트를 직접 가리키도록 갱신
    return parent[x]
```

```
경로 압축 전              경로 압축 후 (Find(1) 수행)

  4                            4
  |                          / | \
  3            →            1  2  3
  |
  2
  |
  1
```

<br>

### 7. 최적화 2 — 랭크 기반 합치기(Union by Rank)

Union 시 항상 **높이(랭크)가 낮은 트리를 높은 트리 밑에** 붙여 트리의 높이 증가를 최소화한다. 랭크 대신 **집합의 크기**를 기준으로 작은 집합을 큰 집합에 붙이는 **Union by Size** 방식도 동일한 효과를 낸다.

```python
rank = [0] * (n + 1)

def union(a, b):
    root_a, root_b = find(a), find(b)
    if root_a == root_b:
        return
    if rank[root_a] < rank[root_b]:      # 낮은 트리를 높은 트리 밑에
        root_a, root_b = root_b, root_a
    parent[root_b] = root_a
    if rank[root_a] == rank[root_b]:     # 높이가 같을 때만 랭크 증가
        rank[root_a] += 1
```

<br>

### 8. 최적화 전후 복잡도 비교

| **구현 방식**                    | **Find**     | **Union**    | **비고**                |
| -------------------------------- | ------------ | ------------ | ----------------------- |
| **기본 구현**                    | O(n)         | O(n)         | 편향 트리 시 최악       |
| **경로 압축만 적용**             | O(log n)     | O(log n)     | 상각(amortized) 기준    |
| **경로 압축 + 랭크 기반 합치기** | **O(α(n))**  | **O(α(n))**  | **사실상 O(1)**         |

여기서 **α(n)** 은 **애커만 함수의 역함수**로, 현실적인 모든 입력 크기(n ≤ 10^80)에서 **5 이하**인 매우 느리게 증가하는 함수다. 따라서 두 최적화를 함께 적용하면 연산당 **거의 상수 시간**으로 동작한다.

> 💡 α(n)은 이론적으로는 상수가 아니지만, 실무와 코딩 테스트 범위에서는 **O(1)로 간주**해도 무방하다.

<br>

### 9. 활용 사례

- **크루스칼 MST**: 간선을 가중치 순으로 정렬한 뒤, 사이클을 만들지 않는 간선만 Union으로 채택한다 (algorithm unit16 참고)
- **사이클 판별**: 간선의 두 정점이 **이미 같은 루트**를 가지면 그 간선은 사이클을 형성한다
- **네트워크 연결 확인**: 두 컴퓨터(노드)가 같은 집합에 속하는지로 **연결 여부**를 O(α(n))에 판별한다

```python
# 사이클 판별 예시
for a, b in edges:
    if find(a) == find(b):
        print("사이클 발생")  # 같은 집합의 두 정점을 다시 연결
        break
    union(a, b)
```

❗️**주의**: 유니온-파인드는 집합의 **분리(Split) 연산은 지원하지 않는다**. 한 번 합쳐진 집합은 되돌릴 수 없으므로, 연결이 끊기는 상황을 다루는 문제에는 **쿼리를 역순으로 처리**하는 기법을 함께 사용한다.
